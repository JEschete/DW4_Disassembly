# Repository Architecture

## Ownership Boundaries

### `src/`

Exact assembly source. `src/banks/` is generated by extraction but tracked so changes are reviewable and an ordinary build does not require the reference ROM. `src/constants/` is maintained source.

### `config/`

Durable inputs and reviewed evidence ledgers. These files control labels, classifications, code seeds and exclusions, pointer tables (including RTS-dispatch tables), the BRK and JSR inline-operand ABI, indirect jumps, the analyzer warning ledger and manifest, intentional code/data overlaps, routine contracts, assets, runtime paths, and save fields.

### `analysis/`

Generated evidence retained because it is reviewed, consumed by later analysis, or enforced by the completion gate. It is not general documentation. Logs, rendered previews, and intermediate Ghidra shards are excluded.

### `scripts/`

Portable orchestration for extraction, static analysis, runtime tracing, and verification. Machine-specific dependencies are supplied through parameters or environment variables documented in `BUILDING.md`.

### `tools/`

Project-owned tooling and modified vendored source. Generated executables and build intermediates are ignored.

### `third_party/`

Pinned clean upstream source dependencies represented as Git submodules.

### `docs/`

Human-authored documentation. `STATUS.md` owns current metrics, `BANK_MAP.md` owns human-readable bank roles, and `DECOMPILATION_NOTES.md` preserves the historical engineering record.

## Generated And Tracked

The following generated artifacts are intentionally tracked:

- `src/banks/bank_00.asm` through `bank_1F.asm`
- Current classification, code, pointer, routine, runtime, save, text, and warning reports under `analysis/`
- Runtime trace TSV files used as durable evidence, including stack-correlated inline-call resumes

Tracking these files makes extraction changes reviewable and permits exact assembly from a checkout without access to the reference ROM.

## Generated And Ignored

- `build/` and compiler intermediates
- `work/` extraction, Ghidra, cc65, and FCEUX scratch data
- Locally built `tools/da65/`
- Analysis logs, previews, and Ghidra shard intermediates
- IDE state and user-specific project settings

## Copyright Boundary

ROM images, save files, patches, archives, emulator captures, and extracted asset payloads are ignored. The repository tracks authored tooling, metadata, evidence, and assembly source, but never the original or rebuilt game image.

## Acceptance Boundary

A structural change is complete only when:

1. No tracked script requires a developer-specific absolute path.
2. A checkout with initialized submodules builds from tracked assembly.
3. Extraction regenerates the same bank sources and durable reports.
4. `verify-completion.cmd` passes and the rebuilt image matches the reference SHA-256.
